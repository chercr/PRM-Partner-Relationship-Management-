THREE STEPS

从源码到可用工作区

以下命令适用于已经安装 Git、Docker 和 Docker Compose 的 Linux 服务器。

01

下载项目

克隆 GitHub 仓库，并进入项目目录。

git clone https://github.com/chercr/PRM-Partner-Relationship-Management-.git
cd PRM-Partner-Relationship-Management-
02

设置管理员账号和密码

复制环境变量示例文件，然后编辑 `.env`。生产环境首次启动必须提供自己的强密码。

cp .env.example .env
# 编辑 .env，至少填写：
ADMIN_USERNAME=admin
ADMIN_PASSWORD=替换为你的强密码
不要使用示例密码部署到公网

密码至少 8 位并包含字母和数字。建议结合大写字母、小写字母、数字和符号，并妥善保管 `.env` 文件。

03

构建并启动

Docker 会完成依赖安装、前端构建、后端打包，并在后台启动服务。

docker compose up -d --build

启动后访问 `http://服务器地址:3001`。如需对外提供服务，建议使用反向代理配置域名与 HTTPS。

ENVIRONMENT & SECURITY

部署时需要理解的配置

密码、会话 Cookie 和数据目录是正式上线前最重要的三项设置。

配置项建议值 / 示例作用
ADMIN_USERNAMEadmin初始管理员账号。其他成员可在登录页注册，管理员可管理成员角色与状态。
ADMIN_PASSWORD自定义强密码生产环境首次启动必填；显式配置后，重启会以环境变量为准。
COOKIE_SECUREtrue 或 falseHTTPS 部署设为 true；纯 HTTP 内网环境保持 false，否则浏览器不会发送安全 Cookie。
PORT3001直接 Node 运行时可通过 PORT 调整；Docker Compose 默认映射 3001:3001，如需修改请同步调整 compose 的端口映射。
./data:/app/dataDocker Compose 已配置持久化 SQLite 数据库和备份，容器升级时不要删除。
备份不要只留在同一台服务器

系统会每 24 小时自动备份，也支持页面手动备份。正式数据建议再复制到另一台机器或对象存储，并定期验证备份是否可恢复。

DEPLOYMENT FAQ

常见部署问题

需要另外安装 MySQL 或 PostgreSQL 吗？

不需要。当前使用 Node.js 内置 SQLite，数据库文件位于持久化的 data 目录。首次启动会创建必要的数据表。

可以多个人使用不同账号和权限吗？

支持。当前为单租户、多用户模式，成员可在登录页注册，管理员可调整角色、停用或删除账号。普通成员共享业务数据，但不能管理成员或清空数据；复杂角色权限和操作审计暂未提供。

为什么配置 HTTPS 后还要修改 COOKIE_SECURE？

设为 true 后，会话 Cookie 只会通过 HTTPS 发送，有助于降低明文传输风险。如果仍在纯 HTTP 内网运行，应保持 false，否则可能无法保持登录。

更新程序时如何保留数据？

保留宿主机 data 目录并重新构建容器即可。更新前建议先手动备份，并将备份文件复制到安全位置，再核对数据库迁移和页面功能。

可以直接使用 npm 启动吗？

可以。Node.js 24+ 环境下先执行 npm install 和 npm run build，再使用 npm start。生产部署仍需自行设置 ADMIN_PASSWORD，并妥善保护 data 目录。
